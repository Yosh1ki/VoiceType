# VoiceType

VoiceTypeは、話した内容を文字起こしして、使っているアプリへ入力するmacOSメニューバーアプリです。WhisperKitによるローカル文字起こしを標準とし、OpenAI APIを使ったCloud文字起こし・文章整形にも対応しています。

**設定したキー → 話しながらローカルWhisper文字起こし → 同じキー → 残りを確定 → 任意でAI整形 → 元のアプリへ入力**

現在は[ソースコード](https://github.com/Yosh1ki/VoiceType)とビルド手順を公開しています。ビルド済みアプリの配布はまだありません。

## まず使ってみる

### 必要な環境

- アプリの実行対象: macOS 14以降
- ソースのビルド: Xcode 26以降と、そのXcodeを実行できるmacOS
- ビルド確認環境: Xcode 26.6 / Apple Silicon Mac。Intel Macでの実動作は未検証です
- Swift Packageの取得と初回のローカルモデル取得にはインターネット接続が必要です

Xcode 26にはmacOS 15.6以降が必要です。確認済みのXcode 26.6にはmacOS 26.2以降の26.xが必要です。バージョンごとの対応OSは[Apple公式のXcodeシステム要件](https://developer.apple.com/xcode/system-requirements/)をご確認ください。macOS 14ではXcode 26を実行できないため、この手順でソースからビルドするにはOSの更新が必要です。

ローカルビルドにはApple Developerアカウントや開発者チームの指定は不要です。既定の署名設定で実行できます。

### APIキーが必要な機能

| 構成 | OpenAI APIキー | OpenAIへ送るデータ |
| --- | --- | --- |
| ローカル文字起こし + AI整形OFF | 不要 | 送信しません |
| ローカル文字起こし + AI整形ON | 必要 | 文字起こし済みテキストとユーザー辞書全文 |
| OpenAI Cloud文字起こし | 必要 | 録音音声。AI整形もONなら、文字起こし済みテキストとユーザー辞書全文も送信します |

OpenAIを使う場合は、[OpenAI Platform](https://platform.openai.com/api-keys)でご自身のAPIキーを作成してください。API利用料金は、そのキーに紐づく利用者自身のOpenAIアカウント・プロジェクトに課金されます。料金と利用可能なモデルは、[OpenAI公式の料金ページ](https://developers.openai.com/api/docs/pricing)をご確認ください。

VoiceTypeが使うモデルは、Cloud文字起こしが[`gpt-transcribe`](https://developers.openai.com/api/docs/models/gpt-transcribe)、AI整形が[`gpt-6-luna`](https://developers.openai.com/api/docs/models/gpt-6-luna)です。モデル名はソースコード内で設定されています。

### ソースから起動する

1. ターミナルでリポジトリを取得し、Xcodeで開きます。

   ```sh
   git clone https://github.com/Yosh1ki/VoiceType.git
   cd VoiceType
   open VoiceType.xcodeproj
   ```

2. XcodeがSwift Package（`argmax-oss-swift`）を解決するまで待ち、`VoiceType` schemeと実行先の`My Mac`を選択します。
3. Run（`⌘R`）で起動します。
4. メニューバーのマイクアイコンから**設定**を開きます。Cloud文字起こしやAI整形を使う場合は、ご自身のAPIキーを入力して**APIキーを保存**を押します。Cloudで使う場合は、文字起こし方法を**OpenAI Cloud**へ切り替えます。ローカルだけで使う場合は、**文字起こし後にAIで自然な文章へ整形**をOFFにします。
5. ローカル方式では、モデルの**準備完了**を確認します。起動時に自動準備され、初回は約626MBのモデルをダウンロードします。
6. **アクセシビリティ設定を開く**を押し、macOSの「システム設定 > プライバシーとセキュリティ > アクセシビリティ」でVoiceTypeをONにします。
7. 設定の「動作 > 音声入力の開始・終了キー」で使いたいキーを選択します。変更はすぐ反映され、再起動後も保存されます。
8. Slack / Chrome / VS Code / ChatGPT / Notesなどのテキスト欄へカーソルを置き、選択したキーで録音を開始します。初回録音時にmacOSから確認される**マイク権限**を許可してください。同じキーをもう一度押すと録音を終了し、結果を入力します。

初期設定ではAI整形と履歴保存がONです。APIキーが未設定の場合、AI整形はスキップされます。キーを保存すると、次の録音から設定に従ってAI整形が実行されます。送信データや保存内容は下の「データの取り扱い」もご確認ください。

fn・Shiftは単独で押して離したときに切り替わります。ほかのキーと組み合わせた場合は録音を切り替えません。Shiftの大文字入力やショートカットは通常どおり使えます。fnで絵文字やmacOSの音声入力が開く場合は、「システム設定 > キーボード」の「🌐キーを押して」を「何もしない」に設定してください。

キーが反応しない場合も、メニューバーの「録音を止めて入力」ボタンから終了できます。

## 主な機能

- メニューバー常駐。メニューの「履歴・メイン画面を開く」から履歴と設定へアクセス
- 今日の文字数（空白・改行を除く）・入力回数・録音時間を表示
- 検索付きローカル履歴、原文・確定文の確認、コピー・再整形・削除
- 履歴は `~/Library/Application Support/VoiceType/history.json` に保存。設定で保存をOFFにできます
- 集計は保存された確定文が対象です。再コピー・再整形で回数は増えず、削除すると集計からも除かれます。入力先への反映完了を測るものではありません
- 録音中は小さな「録音中」表示と「確定」「中止」ボタン。ショートカットやメニューバーからも操作可能
- 設定で開始・終了キーを選択（Caps Lock / fn / 左Shift / 右Shift、初期値はCaps Lock）
- マイク録音
- **WhisperKitでローカル文字起こし（標準）**
- 発話言語を自動判定し、英語は英語、日本語は日本語のまま文字起こし（AI整形でも翻訳しません）
- ローカル認識では無音部分と低信頼度・過度に反復した結果を除外し、発話のない定型文の生成を抑制
- 初回のみWhisperモデルをダウンロードし、以後はMac内で推論
- 設定からOpenAI `gpt-transcribe`へ切り替え可能
- OpenAI APIキーがある場合だけ、文字起こし後のAI文章整形を利用可能
- フィラー、言い直し、句読点、改行の整理
- 日本語・英語に対応したユーザー辞書（1行1語、変換確定後に「辞書を保存」）。辞書の適用にはAI整形とAPIキーが必要です
- クリップボード + Cmd+V で現在のカーソル位置へ自動入力
- 録音開始時のアプリを記録し、メニューバー操作後もそのアプリへ戻して自動入力（復帰できない場合はクリップボードへコピー）
- 録音・処理の中止、5分経過時の自動確定、文字起こし失敗時の自動破棄
- APIキーをmacOS Keychainへ保存
- 録音中/処理中のフローティングHUD

## ローカルWhisper

VoiceTypeはArgmaxの `WhisperKit` をSwift Package Manager経由で利用します。

- Package: `https://github.com/argmaxinc/argmax-oss-swift.git`
- Product: `WhisperKit`
- Model: `large-v3-v20240930_626MB`

ローカル方式では起動時にモデルをバックグラウンドで準備します。初回は自動ダウンロードが行われます。設定画面の「ローカルモデルを今すぐ準備」から再試行することもできます。準備中でも録音を開始でき、準備ができ次第、認識を進めます。

録音中は16kHzの音声をメモリに保持し、開始から約4秒後、その後は約2秒ごと（認識中は完了後）に未確定部分を認識します。短い録音では終了時に一度だけ認識し、録音中の認識結果を再利用できる場合は終了時の再認識を省きます。重複する認識区間を除外してから全文をAI整形します。録音中の認識が失敗した場合は、終了後に音声全体を再処理します。Cloud方式は従来どおり録音ファイルを終了後に送信します。

録音は最長5分で自動確定します。ローカル方式で無音と判定した場合や、認識結果が空の場合は、通知せず録音を自動破棄し、次の録音を開始できます。通信障害などで文字起こしに失敗した場合も、エラー内容を表示したうえで録音を自動破棄します。前の録音を手動で破棄する操作は不要です。AI整形は低遅延設定で実行し、10秒以内に応答がなければ認識済みの文章をそのまま入力またはコピーします。処理中の中止は、実行中の認識・通信が終了してから完了します。

処理成功後、メニューに開始所要時間と終了後の所要時間（認識・整形・入力要求）を表示します。入力要求はCmd+Vイベント送出までの時間で、入力先アプリの描画完了時間は含みません。モデル準備と各処理の時間はmacOSのログにも記録します（subsystem: `VoiceType`, category: `Performance`）。音声や文章そのものはこの計測ログに記録しません。

## データの取り扱い

### 外部へ送信するデータ

- **ローカル文字起こし:** 音声はMac内で処理します。初回のモデル取得には外部通信があります。
- **OpenAI Cloud文字起こし:** 録音音声をOpenAIの`/v1/audio/transcriptions`へ送信します。
- **AI整形・履歴の再整形:** 文字起こし済みテキストと登録されたユーザー辞書全文をOpenAIの`/v1/responses`へ送信します。ローカル認識と組み合わせても、この送信は発生します。辞書に登録した名前や用語も送信対象です。

APIキーはmacOS Keychainへ保存し、OpenAIへの通信時に認証のために使用します。VoiceType独自の中継サーバーはありません。APIキーをソースコードへ書き込む必要はありません。

### このMacに保存するデータ

- **設定・辞書:** macOSのUserDefaultsへ保存します。
- **履歴:** `~/Library/Application Support/VoiceType/history.json`へ、原文・確定した文章・日時・録音時間・アプリ名・入力結果を保存します。アプリ独自の暗号化を行わない平文JSONです。音声は履歴に保存しません。設定で履歴保存をOFFにしても既存の履歴は残り、メイン画面から削除できます。
- **録音:** ローカル方式では音声をメモリに保持します。Cloud方式ではmacOSの一時ディレクトリへ`voicetype-<UUID>.m4a`として保存します。処理成功・中止・文字起こし失敗時には録音を破棄し、一時ファイルの削除を行います。録音中のクラッシュや強制終了、削除の失敗などでは一時ファイルが残る可能性があり、次回起動時の自動削除は行いません。
- **クリップボード:** 確定した文章をコピーします。自動入力OFFでもコピーされ、以前の内容は復元しません。

マイク権限は録音のために使用します。アクセシビリティ権限は、開始・終了キーの監視と元のアプリへの復帰・Cmd+Vによる自動入力のために使用します。

## 注意

- 初回モデル取得にはインターネット接続が必要です。
- `large-v3-v20240930_626MB` のモデル保存分だけディスク容量を使います。
- ローカル推論中はCPU/GPU/Neural Engineとメモリを使用します。
- App Sandboxは有効にしていません。ショートカットの監視とカーソル位置への自動入力にアクセシビリティ権限を使用します。
- 開始・終了キーが他アプリと競合する場合は、設定から別のキーに変更してください。
- 自動入力OFFの場合でも、結果はクリップボードへコピーされます。
- クリップボードの以前の内容は復元しません。

## 開発・ビルド

リポジトリのルートでロジックテストを実行できます。テストでは録音やAPI呼び出しは行いません。

```sh
./Scripts/test.sh
```

Release構成のアプリを作る場合は、次を実行します。

```sh
./Scripts/build.sh
open build/Release/VoiceType.app
```

出力先は`build/Release/VoiceType.app`です。ビルドスクリプトはローカル実行用のad hoc署名を使用します。他のMacへ配布するアプリのDeveloper ID署名・公証は別途必要です。

## メイン画面と日本語入力

メイン画面の左側から「履歴」「設定」を切り替えます。履歴を開くと原文と確定文を確認できます。「再整形」は原文とユーザー辞書全文をOpenAIへ送信して履歴内の文章を更新し、自動入力は行いません。既存の履歴を後から復元することはできず、この版で確定した入力から蓄積します。

VoiceTypeの画面を操作している間は、Caps Lockなどを日本語入力に使えるよう音声入力ショートカットを停止します。入力先アプリへ戻ると再び有効になります。辞書編集にはmacOSの標準テキスト入力を使い、変換途中の文字を外部の状態更新で上書きしません。

録音中の途中テキストは表示しません。ローカル方式の内部認識は録音中も継続し、Cloud方式は終了後に文字起こしします。

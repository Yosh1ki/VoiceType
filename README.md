# VoiceType — Local Whisper Edition

自分用のmacOS音声入力アプリです。

**設定したキー → 話しながらローカルWhisper文字起こし → 同じキー → 残りを確定 → 任意でAI整形 → 元のアプリへ入力**

## この版でできること

- メニューバー常駐。メニューの「履歴・メイン画面を開く」から履歴と設定へアクセス
- 今日の文字数（空白・改行を除く）・入力回数・録音時間を表示
- 検索付きローカル履歴、原文・確定文の確認、コピー・再整形・削除
- 履歴は `~/Library/Application Support/VoiceType/history.json` に保存。設定で保存をOFFにできます
- 集計は保存された確定文が対象です。再コピー・再整形で回数は増えず、削除すると集計からも除かれます。入力先への反映完了を測るものではありません
- 録音中は小さな「録音中」表示と「確定」「中止」ボタン。ショートカットやメニューバーからも操作可能
- 設定で開始・終了キーを選択（Caps Lock / fn / 左Shift / 右Shift、初期値はCaps Lock）
- マイク録音
- **WhisperKitで完全ローカル文字起こし（標準）**
- 発話言語を自動判定し、英語は英語、日本語は日本語のまま文字起こし（AI整形でも翻訳しません）
- ローカル認識では無音部分と低信頼度・過度に反復した結果を除外し、発話のない定型文の生成を抑制
- 初回のみWhisperモデルをダウンロードし、以後はMac内で推論
- 設定からOpenAI `gpt-transcribe`へ切り替え可能
- OpenAI APIキーがある場合だけ、文字起こし後のAI文章整形を利用可能
- フィラー、言い直し、句読点、改行の整理
- 日本語・英語に対応したユーザー辞書（1行1語、変換確定後に「辞書を保存」）。辞書の適用にはAI整形とAPIキーが必要です
- クリップボード + Cmd+V で現在のカーソル位置へ自動入力
- 録音開始時のアプリを記録し、メニューバー操作後もそのアプリへ戻して自動入力（復帰できない場合はクリップボードへコピー）
- 録音・処理の中止、5分経過時の自動確定、文字起こし失敗時の再試行
- APIキーをmacOS Keychainへ保存
- 録音中/処理中のフローティングHUD

## ローカルWhisper

VoiceTypeはArgmaxの `WhisperKit` をSwift Package Manager経由で利用します。

- Package: `https://github.com/argmaxinc/argmax-oss-swift.git`
- Product: `WhisperKit`
- Model: `large-v3-v20240930_626MB`
- macOS 14+ / Xcode 16+

ローカル方式では起動時にモデルをバックグラウンドで準備します。初回は自動ダウンロードが行われます。設定画面の「ローカルモデルを今すぐ準備」から再試行することもできます。準備中でも録音を開始でき、準備ができ次第、認識を進めます。

録音中は16kHzの音声をメモリに保持し、開始から約4秒後、その後は約2秒ごと（認識中は完了後）に未確定部分を認識します。短い録音では終了時に一度だけ認識し、録音中の認識結果を再利用できる場合は終了時の再認識を省きます。重複する認識区間を除外してから全文をAI整形します。録音中の認識が失敗した場合は、終了後に音声全体を再処理します。Cloud方式は従来どおり録音ファイルを終了後に送信します。

録音は最長5分で自動確定します。文字起こしに失敗した録音はアプリ起動中に保持し、メニューから再試行または破棄できます。AI整形は低遅延設定で実行し、10秒以内に応答がなければ認識済みの文章をそのまま入力またはコピーします。処理中の中止は、実行中の認識・通信が終了してから完了します。

処理成功後、メニューに開始所要時間と終了後の所要時間（認識・整形・入力要求）を表示します。入力要求はCmd+Vイベント送出までの時間で、入力先アプリの描画完了時間は含みません。モデル準備と各処理の時間はmacOSのログにも記録します（subsystem: `VoiceType`, category: `Performance`）。音声や文章そのものはこの計測ログに記録しません。

## 起動方法

1. `VoiceType.xcodeproj` をXcode 16以降で開く
2. XcodeがSwift Package (`argmax-oss-swift`) を解決するまで待つ
3. `VoiceType` schemeを選択
4. Run (`⌘R`)
5. 初回録音時にマイク権限を許可
6. メニューバーのマイクアイコン → **設定**
7. ローカルモデルの「準備完了」を確認する（起動時に自動準備されます）
8. **アクセシビリティ設定を開く**を押し、macOSの「システム設定 > プライバシーとセキュリティ > アクセシビリティ」でVoiceTypeをON
9. 設定の「動作 > 音声入力の開始・終了キー」で使いたいキーを選択（変更はすぐ反映され、再起動後も保存されます）
10. Slack / Chrome / VS Code / ChatGPT / Notesなどのテキスト欄へカーソルを置いて、選択したキーで録音を開始し、もう一度同じキーで終了

fn・Shiftは単独で押して離したときに切り替わります。ほかのキーと組み合わせた場合は録音を切り替えません。Shiftの大文字入力やショートカットは通常どおり使えます。fnで絵文字やmacOSの音声入力が開く場合は、「システム設定 > キーボード」の「🌐キーを押して」を「何もしない」に設定してください。

キーが反応しない場合も、メニューバーの「録音を止めて入力」ボタンから終了できます。

## OpenAI APIキーは必須？

**ローカル文字起こしだけなら不要です。**

APIキーが必要なのは次の場合です。

- 「文字起こし後にAIで自然な文章へ整形」を使う
- 音声認識方法を「OpenAI Cloud」に切り替える

ローカル + AI整形ONの構成では、音声ファイル自体はOpenAIへ送りません。WhisperKitで文字列にした後、そのテキストだけを文章整形APIへ送ります。

## 注意

- 初回モデル取得にはインターネット接続が必要です。
- `large-v3-v20240930_626MB` のモデル保存分だけディスク容量を使います。
- ローカル推論中はCPU/GPU/Neural Engineとメモリを使用します。
- このMVPは**個人利用前提**で、App Sandboxを有効にしていません。カーソル位置への擬似Cmd+VにAccessibility権限が必要なためです。
- 開始・終了キーが他アプリと競合する場合は、設定から別のキーに変更してください。
- 自動入力OFFの場合でも、結果はクリップボードへコピーされます。
- クリップボードの以前の内容は復元しません。

## メイン画面と日本語入力

メイン画面の左側から「履歴」「設定」を切り替えます。履歴を開くと原文と確定文を確認できます。「再整形」は原文をOpenAIへ送信して履歴内の文章を更新し、自動入力は行いません。既存の履歴を後から復元することはできず、この版で確定した入力から蓄積します。

VoiceTypeの画面を操作している間は、Caps Lockなどを日本語入力に使えるよう音声入力ショートカットを停止します。入力先アプリへ戻ると再び有効になります。辞書編集にはmacOSの標準テキスト入力を使い、変換途中の文字を外部の状態更新で上書きしません。

録音中の途中テキストは表示しません。ローカル方式の内部認識は録音中も継続し、Cloud方式は終了後に文字起こしします。
